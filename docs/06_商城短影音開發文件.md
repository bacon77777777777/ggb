## 0. 一句話

商城底部導航中間加一格「影音」：直式短影音上下滑（像 Reels），**每支影片一定掛商品**，
點商品卡直接進 `/sell/<id>` 買。發布者是**賣家與官方**，一般玩家第一期不開。

## 1. 決策紀錄（老闆 2026-08-15）

| 項目 | 決定 | 備註 |
|---|---|---|
| 定位 | 帶貨短影音，不是社群 | 每支至少掛 1 件上架中商品，畫面永遠有出口 |
| 中間鈕 | 「看」影音（feed 入口） | 發布放影音頁右上「＋」與「我的」 |
| 誰能發 | 賣家（有上架中商品）＋官方 | 一般玩家第二期再議 |
| 前置 | **先做一天原型**驗手感 | 抓 5 支現成直式影片放 R2，做播放頁丟老闆 iPhone 滑；不順就不往下 |
| 冷啟動 | 不種假影片 | 官方每天固定產出 3–5 支；讚數要不要種待議 |
| 留言 | 第一期先不做（待拍板） | 做的話直接搬情報頁那套（news_comments） |

**待老闆拍板**（見 §10）：轉檔要不要用付費服務、留言是否第一期、一般玩家何時開、讚數是否種。

## 2. 網頁平台的硬限制與對策（做之前要知道）

| 限制 | 影響 | 對策 |
|---|---|---|
| 自動播放必須靜音（iOS／Android） | 第一支沒聲音 | 首次點「開聲音」後全域記住；**固定 3 個 `<video>` 循環換 `src`**（iOS 只認被點過的元素，每支 new 一個會再被靜音） |
| iOS 低耗電模式擋自動播放 | 影片停在封面 | 一律有封面 + 播放鈕；`play()` 被拒就顯示鈕，不要當錯誤 |
| Safari 分頁模式上下工具列藏不掉 | 沉浸感打折 | 容器用 `100dvh` + `position:fixed`；加到主畫面（PWA）才全螢幕，接受 |
| iPhone 預設錄 **HEVC**（.mov） | Safari 能播，Android／Chrome 黑畫面 | 上傳端偵測 codec，HEVC 一律擋下並提示改「相容性最佳」；或走轉檔（§10 待拍板） |
| 沒有轉檔＝沒有自適應碼率 | 4G 訊號差轉圈 | 上傳限制（≤30 秒、≤50MB、≤1080p）+ 封面先出 + 只預載下一支 |
| 不能背景預載 | 只能偷偷抓下一支的前幾秒 | `preload="auto"` 只給下一支，其餘 `metadata` |
| 手勢衝突 | 雙擊縮放、長按存圖、Android 下拉刷新、iOS 邊緣返回 | 那頁關：`touch-action:manipulation`、`-webkit-touch-callout:none`、`user-select:none`、`overscroll-behavior:contain`；互動只做垂直方向 |
| 記憶體 | 掛太多 video iOS 直接殺分頁 | 同時只存在 3 個 `<video>`（上／中／下） |

**滑動一定用原生 `scroll-snap-type: y mandatory`**（硬體捲動），不要用 JS 算 transform——JS 拖一定卡。

## 3. 分期

### 第 0 期：原型（1 天）
- 不做資料表、不做上傳。手動抓 5 支現成直式 MP4（H.264）放 R2 `reels-proto/`
- `/sell/reels` 播放頁：原生 snap 捲動、3 支循環播放器、靜音→開聲、封面、右側按鈕先假的、底部商品卡假的
- 驗收：老闆 iPhone Safari 分頁模式 + 加到主畫面各滑一次；Android Chrome 一次；低耗電模式一次
- **不順就停**，順才進第一期

### 第一期（可上線的最小版本）
- migration：`sell_posts` / `sell_post_likes` / `sell_post_views`（§6）
- 賣家上傳：「我的」→ 上傳影片、選掛哪件商品、寫一句話 → `pending`
- 後台「商城影音」審核頁：列表＋播放＋放行／退回／下架（照上架審核那套）
- 播放頁：時間序 feed、讚、分享（`/sell/reels/<id>`）、商品卡→`/sell/<id>`、賣家頭像→店舖
- 底部導航中間鈕；feature flag `sell_reels`
- 檢舉：`sell_reports.target_type` 加 `'post'`

### 第二期
- 留言（搬 news_comments 那套）、追蹤賣家、收藏、瀏覽數、通知（有人讚／留言）
- 推薦排序（§8）、官方後台代發

### 第三期
- 官方開獎精華自動產出、活動 hashtag、影片內直接開抽（抽獎聯動）、一般玩家發布

## 5. 前台播放頁規格（`frontend/app/sell/reels/`）

### 5.1 檔案
```
app/sell/reels/page.tsx            feed（'use client'，useFeatureGate('sell')）
app/sell/reels/[id]/page.tsx       同一個元件，帶 startId
app/sell/reels/[id]/layout.tsx     generateMetadata（og:title=caption、og:image=poster、og:video）
app/sell/reels/new/page.tsx        上傳
components/sell/reels/ReelsFeed.tsx      捲動容器 + 3 播放器池
components/sell/reels/ReelPlayer.tsx     單支：video/poster/進度條/暫停
components/sell/reels/ReelOverlay.tsx    右側按鈕列 + 左下標題 + 商品卡
components/sell/reels/useReelsAudio.ts   全域聲音狀態（首次點開後記住，sessionStorage）
lib/sell/reels.ts                        資料層：feed 分頁、讚、瀏覽埋點
```

### 5.2 DOM 與捲動
```html
<div class="reels" style="height:100dvh; overflow-y:auto; scroll-snap-type:y mandatory; overscroll-behavior:contain">
  <section class="reel" style="height:100dvh; scroll-snap-align:start; scroll-snap-stop:always">…</section>
  <!-- 每支一個 section；只有「目前 ±1」的 section 裡真的有 <video>，其餘只有 poster <img> -->
</div>
```
- `IntersectionObserver`（threshold 0.6）決定「目前這支」：進入→`play()`、離開→`pause()` + `currentTime=0`
- **播放器池**：3 個 `<video>` 元素在元件掛載時就建立，之後只換 `src`／`poster`，永不 new。
  首次「開聲音」時對三個都 `muted=false; play(); pause()`（在同一個點擊事件裡）解鎖
- `<video playsinline webkit-playsinline muted loop preload="metadata">`；下一支 `preload="auto"`
- `play()` 回傳的 promise 被 reject（低耗電／未互動）→ 顯示中央播放鈕，不彈錯誤
- 進度條用 `timeupdate` 節流到 4 fps 畫，不要每 frame

### 5.3 互動
- 單擊：暫停／播放；雙擊：讚（心形飛出）；長按：關掉（不做選單，第一期）
- 右側：讚（數字）／留言（第二期，先隱藏）／分享／收藏（第二期）
- 左下：賣家頭像＋名稱（→ 店舖 `?v=shop&s=`，走引擎網址）、標題兩行截斷「更多」展開、**商品卡**（縮圖／標題／價格／「看商品」→ `/sell/<id>`）
- 分享：同商品頁——手機 `navigator.share({title, url})`、桌機複製＋toast「連結已複製」
- 左上返回：`history.length>1 ? router.back() : router.push('/sell')`
- 底部導航：同引擎五格，中間為 active

### 5.4 資料載入
- `sell_reels_feed(p_cursor, p_limit=10)` 游標分頁（依 `sort_key` 排序，見 §8）；滑到倒數第 3 支預取下一頁
- 深連結 `/sell/reels/<id>`：先 `sell_reels_one(id)` 放第一支，後面接 feed（去重）
- 找不到（下架／不存在）：顯示「影片不存在或已下架」＋返回

### 5.5 埋點
- `reel_view`（開始播）、`reel_watch`（離開時帶秒數／完成率）、`reel_product_click`、`reel_share`、`reel_like`
- 寫 `sell_post_views`（一支一天一人一筆，去重）與 `user_event_logs`；**排除 is_bot**

### 5.6 文案原則
- 玩家看得到的字串不出現路徑／欄位／狀態碼（見 CLAUDE.md「前台文案原則」）
- Loading 一律 `ProductLoadingScreen`，不自創 spinner

## 6. 資料模型（migration 草稿，編號先 `git fetch` 看 origin 最新，目前下一號 **580**）

```sql
-- 580_sell_posts.sql（草稿，動工前再核一次欄位）
CREATE TABLE public.sell_posts (
  id            bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  seller_id     uuid NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  is_official   boolean NOT NULL DEFAULT false,
  video_url     text NOT NULL,             -- R2 公網網址（reels/<uuid>.mp4）
  poster_url    text NOT NULL,             -- R2（reels/<uuid>.webp），前端抓第一格
  duration_sec  int  NOT NULL CHECK (duration_sec BETWEEN 1 AND 60),
  width         int, height int,           -- 供版面判斷（直式 9:16 為主）
  caption       text NOT NULL DEFAULT '',
  listing_ids   bigint[] NOT NULL DEFAULT '{}',   -- 至少 1 件；trigger 檢查都是 seller 自己的、active
  status        text NOT NULL DEFAULT 'pending'
                CHECK (status IN ('pending','active','rejected','removed')),
  review_note   text, reviewed_at timestamptz, reviewed_by text,
  like_count    int NOT NULL DEFAULT 0,
  comment_count int NOT NULL DEFAULT 0,
  view_count    int NOT NULL DEFAULT 0,
  sort_key      numeric NOT NULL DEFAULT 0,      -- 排序分數（§8），cron 每小時重算或 trigger 增量
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON public.sell_posts (status, sort_key DESC, id DESC);
CREATE INDEX ON public.sell_posts (seller_id, created_at DESC);

CREATE TABLE public.sell_post_likes (
  post_id bigint REFERENCES public.sell_posts(id) ON DELETE CASCADE,
  user_id uuid   REFERENCES public.users(id)      ON DELETE CASCADE,
  created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (post_id, user_id)
);

CREATE TABLE public.sell_post_views (
  post_id bigint REFERENCES public.sell_posts(id) ON DELETE CASCADE,
  user_id uuid,                              -- 未登入可 NULL（配 anon_id）
  anon_id text,
  day     date NOT NULL DEFAULT (now() AT TIME ZONE 'Asia/Taipei')::date,
  watched_sec numeric, completed boolean,
  PRIMARY KEY (post_id, day, COALESCE(user_id::text, anon_id))
);

-- 第二期：sell_post_comments（照 news_comments：id, post_id, user_id, content, parent_id, is_deleted, created_at）
-- 檢舉：ALTER TABLE sell_reports DROP CONSTRAINT ...; ADD CHECK target_type IN ('listing','order','seller','post'); ADD COLUMN post_id bigint REFERENCES sell_posts
```

- **RLS**：`sell_posts` 公開讀 `status='active'`；賣家可讀寫自己的；likes/views 本人寫、公開計數走 RPC。
  ⚠️ CLAUDE.md：開了 RLS 沒 policy 前台會**靜默拿到空陣列**，policy 要跟表一起建
- **Trigger `sell_guard_post`**（照 `sell_guard_listing`）：
  - 停權賣家不能發；`listing_ids` 非空、每件都是本人上架中商品（官方 `is_official` 例外）
  - 非特權者 INSERT 一律 `pending`；改 `video_url/caption/listing_ids` 回 `pending`（防換餌）
  - 狀態只能自行 `removed`，或 `rejected/removed → pending` 重送
- **RPC**（SECURITY DEFINER，照 sell_feed 風格）：
  - `sell_reels_feed(p_cursor numeric, p_limit int)` → 帶賣家名／頭像／等級、掛的商品（id/title/price/image）、我有沒有讚

  - 賣家：`sell_my_posts()`（給「我的」列表）
- 計數欄用 trigger 維護（likes 增減、views 累加），不要每次 count(*)

## 7. 上傳規格

### 7.1 流程
1. 賣家在「我的」→「發布影音」（或影音頁右上「＋」）→ `/sell/reels/new`
2. `<input type="file" accept="video/mp4,video/quicktime" capture="environment">`（iOS 會問相機／圖庫）
3. 前端檢查：時長 ≤ 60 秒（第一期建議 ≤ 30）、檔案 ≤ 50MB、寬高比接近 9:16（橫的提示但不擋）、**codec**：
   用 `<video>` 載入 blob 讀 `videoWidth/duration`；HEVC 偵測用 `canPlayType`／`MediaSource.isTypeSupported('video/mp4; codecs="hvc1"')` 只能知道本機能不能播，
   跨機相容要靠讀 mp4 box（`ftyp/moov` 解析 `hvc1/hev1` vs `avc1`，用輕量 parser 十幾行即可，不要拉 ffmpeg.wasm）
   → HEVC 一律擋：「請到 設定 › 相機 › 格式 選『相容性最佳』再拍一次」（待 §10 拍板是否改走轉檔）
4. 封面：`<video>` seek 到 0.5s → canvas 抓圖 → webp（720 寬）
5. 取 signed URL：`POST /api/upload/reels/sign`（前台 API route，登入 + 賣家資格檢查）→ 回 R2 PUT URL（key `reels/<uuid>.mp4` 與 `reels/<uuid>.webp`）
6. 直傳 R2（`fetch(PUT)`，顯示進度）→ 成功後 `INSERT sell_posts (…, status 'pending')`
7. 顯示「已送出審核，通常 1 個工作天內上架」

### 7.2 R2
- 用既有 bucket（env `R2_*` 前後台都有，見 CLAUDE.md／`frontend/app/api/upload/image/route.ts` 的用法）；**不要另開付費服務**
- 影片走公網網址直接播（`R2_PUBLIC_URL`）；R2 出口免費，CDN 邊緣快取夠用
- 命名 `reels/<uuid>.<ext>`；刪除貼文不刪檔（後台再清）

### 7.3 官方發布
- 第一期先由管理員在後台「商城影音」頁上傳（同一支 API，`is_official=true`、直接 `active`）

## 8. 排序（第一期公式，之後再調）

```
sort_key = ln(1 + like_count*3 + view_count*0.2 + share_count*5)
         + (掛的商品仍 active ? 1.0 : -2.0)
         + is_official ? 0.5 : 0
         - hours_since_created / 36
```
- 每小時 cron 重算（照 `backend/app/api/cron/` 慣例，pg_cron secret 要 hardcode，見 CLAUDE.md）
- 深連結那支永遠排第一，其餘接 feed；同一賣家連續不超過 2 支
- **機器人排除**：計數與 feed 都 `is_bot IS NULL OR is_bot=false`

## 10. 要老闆拍板（動工前確認）

1. **轉檔**：零成本＝上傳端擋 HEVC＋限制檔案（品質靠賣家）；付費＝Cloudflare Stream 之類（上傳→自動轉檔＋HLS＋CDN，量小月費約幾百元）。
   情報系統的「不引付費服務」原則是取材成本，這是核心功能，需另外決定
2. 留言第一期做不做
3. 一般玩家何時能發
4. 讚數要不要像情報頁那樣種（建議不要種假影片；讚數待議）
5. 上傳上限：30 秒還是 60 秒
6. 中間鈕圖示與名稱（「影音」？「動態」？）
