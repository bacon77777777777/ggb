## 一、商品補齊（`/products/import`）

### 現在跑得起來的流程

```
丟檔案（.xlsx/.csv）
  └─ lib/vendorFileParse.ts     純字串處理，零成本、一秒完成
       欄位靠「內容」判斷，不是靠標題：
         ≥50% 中日文字 → 商品名 ／ ≥70% 是 8~14 位數字 → 條碼
       沒標題的欄自動編成「第 N 欄」，直向排列的品項自動群組
  └─ 寫入 import_jobs + import_job_rows，人可以離開

背景補齊（一輪 6 列、同時 2 條、失敗重試 2 次）
  └─ 推進者是「開著的那一頁」，每 3 秒打 /api/admin/import-jobs/[id]/run
     pg_cron 只是沒人看著時的後備，而且只排在 PROD（本機與 STG 沒有 pg_cron）
  └─ lib/productEnricher.ts → enrichRow()
       ① 有條碼 → lib/sources/gashapon.ts 查官方站
          查得到：品名、定價、種類數、主圖、每一款的名字與原廠照片全部到手
          AI 只做「純翻譯」（translateToTW），翻回來的款數對不上就整份不用
       ② 查不到 → 退回 collectPages()：駿河屋條碼搜尋 → 商品頁 → DDG
          再讓 AI 從網頁文字裡抽資料（enrichProduct）。這條本來就比較不準
       ③ 圖片：廠商給的最優先 → 官方站 → 搜圖（最後手段，不準）
       ④ 只給總數的商品，款式平分數量，餘數往前加一
```

### 目前只接了 BANDAI 轉蛋

`lib/sources/gashapon.ts` 是唯一的官方來源。**下一步最有價值的就是照同一個模式再接三個**，
每個都是獨立檔案放在 `lib/sources/`，`enrichRow` 依序試：

| 站 | 涵蓋 | 狀態 | 要解的問題 |
|----|------|------|-----------|
| `gashapon.jp` | BANDAI 轉蛋 | **已接** | — |
| `ichibankuji.com` | 一番賞 | 未接（連得上，200） | 找「用條碼或商品名查」的入口。**對現有廠商 list 幫助最大**，鋼彈那筆就是卡在這 |
| `bandai.co.jp/candy` | 盒玩／食玩 | 未接（連得上，200） | 同上 |
| `takaratomy-arts.co.jp` | T-ARTS 轉蛋 | 未接（連得上，200） | 老闆點名過。`/specials/gacha/` 是 404，要另外找路徑 |

接法照 `gashapon.ts` 抄：一個 `lookupXxx(barcode | name)`，查無回 `null`
讓上層自然退回搜尋路徑。**查無時很多站回的是 200 + 一頁空版面，不是 404**，
一定要靠內容（例如有沒有 h1）判斷，不能只看 status。

### 還可以再做的

1. **`gashapon.jp` 用商品名查**。目前只走 `jan_code`，沒條碼的列完全用不到官方站。
   站上有 `products/result.php?free=<關鍵字>`，可以拿商品名去搜再挑最像的那筆。
2. **官方站查到後補回條碼**。廠商沒填條碼時，反查到官方頁就能把條碼補上，
   下次同一支商品直接命中。
3. **「全N種」對不上時的處理**。現在只在補齊記錄裡寫一句話，
   可以考慮把該列標成需要人工確認，而不是 done。
4. **一番賞的賞等**。官方站有 A賞/B賞/最後賞的結構，接進來之後
   `level` 才填得對，現在一律是空字串或「未分類」。
5. **搜圖那條路本來就不準**。官方站接齊之後可以考慮直接關掉，
   寧可留空讓人補，也不要配一張錯的 —— 老闆的原話是「亂補」。

### 成本

**只有 Claude Haiku 要錢，一列一次呼叫**，約 US$0.009 ≈ 台幣 0.3 元／列，
33 筆的檔案約台幣 8~10 元。官方站命中時輸入變短（只餵品名與款式名），
比走搜尋路徑更便宜。

其餘全部零成本，也守住 CLAUDE.md 那條「不得引入新的付費服務」：
官方站與駿河屋是公開 HTML、DDG 免 API key、圖片走既有 R2 與本地 sharp。
被 Turnstile 擋的站（130point、cardrush）一律放棄不繞。

- 前台 `contexts/PromotionsContext.tsx` + 商品卡角落的「買5送1」標籤

### 老闆定的規則（不要改掉）

1. **買五送一 = 抽 6 次只收 5 次的錢**。實作成「折價」不是「多送一抽」——
   多送一抽要動整段核心抽獎邏輯，折價只多一行，而且正好對上老闆要的帳務呈現。
2. **不跟優惠券疊加**。採「促銷優先，優惠券不吃也不扣」，
   若兩個都算，玩家的券會被默默消耗掉卻只換到一份折扣。
3. **帳務要列滿六抽的錢，再多一項「活動促銷」扣除項**。
4. **成本平台與廠商各半**。
